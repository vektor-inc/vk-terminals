# 組み込み用「使い方・ヘルプ」（#542）

Terminals を組み込むホストだけが `embedded.start()` に次の対を渡す。両方省略すると入口を表示せず、main の専用 IPC も要求を拒否する。片方だけ、型違い、不正パス・プロンプトは起動時の例外とする。既存の `setupPane` / `getSetupStatus` は独立した契約で、変更しない。

```js
{
  help: {
    documentPath: '/absolute/app/resources/help.html',
    cwd: '/absolute/existing/guide-directory',
    prompts: {
      claude: '/vk-orchestrator-helper',
      codex: '$vk-orchestrator-helper',
    },
  },
  getHelpStatus: async ({ signal }) => ({
    engine: 'codex',
    engines: [
      { engine: 'claude', state: 'unavailable', reason: 'Claude Code を利用できません。', preparation: 'Claude Code を導入してログインしてください。' },
      { engine: 'codex', state: 'available' },
    ],
  }),
}
```

## 検証・利用可否

- `documentPath`: 実在する絶対パスの通常ファイル。拡張子は `.html` のみ（大文字小文字は区別しない）。リンクの場合は実体も `.html` に限定し、正規化時に実体パスを保持する。実行可能ファイルを開かせず、ブラウザ向けページに限定するため。
- `cwd`: 実在する絶対パスのディレクトリ。起動時にも存在を再検証し、消えていた場合は別フォルダに切り替えず失敗する。
- `prompts`: `claude` / `codex` の両方が必須。他のエンジンは拒否する。Claude は `^/[a-z0-9-]+$`、Codex は `^\$[a-z0-9-]+$`。改行も禁止する。正規化後の設定はコピーして凍結する。
- `getHelpStatus({ signal })`: 起動後もヘルプ表示・再確認・新規ガイド起動時に呼ぶ。エンジン選択と判定本体はホストの責務。`engine` は利用可能な `claude` / `codex`、または `null`（両方利用できない／不明）。`engines` は両エンジンを重複なしで1件ずつ含む。
- 各項目の `state`: `available` / `unavailable` / `unknown`。選択エンジンは `available` と一致させる。利用可能な項目があるのに `engine: null` も拒否する。
- `reason` / `preparation`: 省略可能な文字列。ただし `unavailable` には両方の非空文字列が必須。各2000文字まで、一部制御文字は禁止。不正な形・矛盾した選択・例外・20秒の時間切れは両方 `unknown` として「確認できませんでした」「再確認」を表示する。未導入とは断定しない。
- 同時確認は1本。20秒後は `signal` を abort する。ホストは abort に応じて処理を終了させること。終了していない間の再確認は unknown を返し、判定処理を積み増さない。
- 文言は main で検証し、renderer は `textContent` だけで表示する。HTML・コマンド・リンクとして解釈しない。

## 表示・起動経路

「設定」の直下に同じサイドバーボタン様式で「使い方・ヘルプ」を置く。矢印なし。設定タブの「バージョン情報」（ホストのディスクリプタ由来。ラベルまたは `id: 'about'` で判定）の直前、無ければ末尾へ挿入する。タブ定義なしの既存設定は「設定」タブにまとめ、設定ディスクリプタが無い場合もヘルプ単独タブを表示できる。

通常は「ドキュメント」「AI に相談」の2ボタンだけを表示する。両エンジンが利用できない場合、AI ボタンの位置に理由・準備手順と再確認ボタンを表示する。確認中・起動中は操作を無効化し、`role=status` で状態を通知する。ボタンは44px以上の高さとし、長文を折り返す。既存設定の配色・フォーカスリングを共用する（現在のデスクトップ設定画面はOSテーマによらずダーク配色）。

IPC は `help:check` / `help:document` / `help:open-guide`。すべて引数なし。渡された余分な引数は使わない。ドキュメントは保持済みパスを再検証し `pathToFileURL` と `shell.openExternal` で開く。フォルダ用 `openPathPolicy`、HTTP(S)限定の `shell:open-external` は緩めない。ドキュメントはAIの利用可否を照会せず開ける。

ガイド起動は内部専用の識別子を用いてペイン共通作成処理を呼ぶ。汎用 `terminal:create` で `guidePane` を受けることは拒否する。HTTP `/api/new-pane` は既存の許可項目だけをrendererに渡し、スマートフォン経由を含めガイドの指定を転送しない。cwd・エンジン・プロンプトを画面から受け取らない。

既存 `renderer/claudeModel.js` のコマンドビルダーに、検証済みプロンプトを単一引用符で追加する。Codex は `--no-daemon` を維持し、`$` はシェル展開されない。入力欄への後送りはしない。ペイン名は「使い方ガイド」。起動コマンドの書き込みが成功してからrendererへ返す。準備・PTY作成・書き込みが失敗したら起動失敗と再試行を表示し、作成途中のPTYを閉じる。

## 重複防止・保存・復元

main と renderer の両方が起動中の要求を1本にまとめる。生存しているガイドのPTYがある場合は再起動もコマンド再送もしない。renderer は同じPTYのペインへフォーカスし、格納中ならグリッドへ戻す。モーダルは成功時に閉じる。

未保存変更があれば「保存して開く」「破棄して開く」「キャンセル」を明示する。保存は既存の全タブ検証・保存処理を通し、検証エラー・保存失敗・設定読み込み失敗の間は起動しない。キャンセル時は設定画面と編集内容を残す。

現在のアプリにはペイン配置やPTYを永続化して起動時に復元する経路がなく、起動ごとに初期ペインを作る。ガイドの識別もmainのメモリだけに保持するため、アプリ再起動時にガイドを自動復元しない。同一mainでrendererが再読込された場合は、次の明示操作時に生存中PTYを再接続する。閉じた後も自動再作成せず、次の明示操作でのみ新規起動する。

## 検証範囲・残る確認

単体テストで設定・状態の拒否、シェルの実際の引数、確認例外・時間切れ、再確認、多重起動・終了・再試行を検証する。画面テストは隔離HOMEで、確認失敗と文言のエスケープ、タブ位置、未保存キャンセル、起動中表示、格納復帰を検証する。実際のホストが渡すドキュメント本文・スキル・判定本体と、実CLIでの案内内容は vk-orchestrator#834 側で結合確認する。CLIが起動後に認証エラーなどで終了すること自体はPTY起動成功とは別で、ガイドの端末出力で確認する。
