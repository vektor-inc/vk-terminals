# アプリ内ブラウザ仕様（issue #590）

## クリック操作

ペイン内 URL、issue タイトル、PR ボタンをクリックするとリンクのそばに「アプリ内で開く」「外部ブラウザで開く ↗」のメニューを出す。開き先を選ぶまではページを開かない。未フォーカスのペインでも最初のクリックで表示する。ペイン内 URL は既存の `terminalLinkClickMode` が `click` なら通常クリック、`modifier` なら ⌘ / Ctrl+クリックでメニューを出す。タイトルと PR は設定に関係なく通常クリックで表示する。修飾キーによる直接起動と新しい設定項目は設けない。

Claude Code と Codex のペイン内 URL は、文字列から検出したリンクと端末の OSC 8 リンクのどちらも同じクリック判定と開き先メニューを使う。

ドラッグ、右クリック、中クリック、ダブルクリックの 2 回目では表示しない。Esc、Tab、外側クリック、ペインのホイールで閉じ、上下矢印で移動し Enter / Space で決定する。メニューは `role=menu` / `menuitem`。ペイン内 URL はクリック位置の右下、タイトルと PR は要素の左下に置き、画面端とサイドバー左端を超えない。初期フォーカスは「アプリ内で開く」。閉じたら元のペインまたは要素にフォーカスを戻す。

## 右サイドバー

再読み込みは、確定した HTTP(S) の URL または再試行できる失敗 URL がある場合に有効にする。初回の URL 送信だけでは有効にせず、文書が未確定の読み込み中は無効にする。表示済みページからの読み込み中は、確定 URL があるため再読み込みできる。

右側のサイドバーにタブの行（後述「タブ」）と操作列を置き、操作列は選んでいるタブのページを操作する。操作列の操作は戻る、進む、再読み込み、ホーム、URL 入力欄、広く表示、外部ブラウザで開く、アプリ内ブラウザを閉じる。URL 入力欄へ URL または検索語を入力し、Enter でページを開く。ドメイン形式の入力は https:// を補い、localhost・IPv4 アドレス・英字を含むポート番号付きの 1 語のホスト名（例: `myserver:3000`）は社内・ローカルのアドレスを外部の検索サービスへ送らないよう http:// を補って開く。それ以外（`16:9` や `10:30` のような数字だけの入力を含む）は Google 検索で開く。送信を受け付けられなかったときは読み込み中の表示を解除し、入力した文字列（応答を待つ間に打ち直した場合はその文字列）を残して、入力欄の下に「ページを開けませんでした。もう一度 Enter を押してください。続けて開けない場合は、アプリを再起動してください。」と案内する。URL のコピー操作は設けない。入力欄は未送信の入力を編集中は保持し、送信後は読み込み先、失敗時は失敗した URL を表示する。外部ブラウザボタンは入力欄の表示とは別に、確定した現在の URL（または一致するダウンロード要求で明示した対象）だけを開く。読み込み中は進行バー、失敗時は失敗先のホスト名と再読み込み・外部ブラウザで開く操作を表示し、後続の読み込み状態通知でも保持する。次の遷移で消す。失敗表示の外部ブラウザ操作は読み込みに失敗した URL を開く。外部ブラウザで開く前に URL を検証する。github.com の 404 ではプライベートリポジトリへのログイン案内と「GitHub にログイン」「閉じる」を表示し、次の遷移まで保持する。

幅は左端のドラッグまたは矢印キーで変更する。通常の下限は 360px、既定は左サイドバーと横並び要素の最小幅を除いた使用可能幅の 45%（480〜720px）。中央のターミナルには `MIN_TERMINAL_WIDTH = 320px` を確保する。左右のサイドバーの併存は、root の CSS 幅から左サイドバーの設定幅を引いた残幅が `320px + 360px` 未満なら不可とする（左が 300px なら root 幅 980px 未満）。右のブラウザを開く、または表示中に幅が狭くなると左を閉じる。左を手動で開いた場合は右を閉じ、その操作を優先する。判定には開閉途中の左の実幅ではなく設定幅を使う。右を閉じても左は自動で開かず、幅を広げても閉じた側は自動で開かない。

左右の排他処理後、表示中の左サイドバーの実幅を除いた幅に「ブラウザ下限 360px ＋ 横並びのペイン予約幅 `max(.grid の横並び時の最小幅, 320px, 列数 × 272px)` ＋ セットアップ状況パネル最小幅 240px」が収まらない場合に、セットアップ状況パネルを帯に畳む。この判定はブラウザの保存幅に依存せず、左右の排他判定とは別に行う。たとえば左 300px・root 980px では左右は併存できるが、セットアップ状況パネルは帯になる。ブラウザを閉じると root 幅 1000px 未満で畳む判定に戻る。帯の「開く」は既存の影つき重ね表示を使う。帯・重ね表示は横並び要素として幅を引かず、横並びのパネルだけ最小幅 240px を引く。

ブラウザ幅の計算に使うグリッド最小幅は常に 320px 以上とする。帯に畳んだ後も `max(MIN_TERMINAL_WIDTH, 12px) = 320px` であり、パネルなし・重ね表示でも 320px を残す。上限は `min(max(0, 使用可能幅 − グリッド最小幅), max(360px, 使用可能幅 − max(グリッド最小幅, 320px, 列数 × 272px)), root の CSS 幅 − 96px)`。中央 320px の確保によって上限が 360px 未満になる場合は、ブラウザを 360px 未満に縮める（root 600px・左を閉じた状態ではブラウザ 280px、中央 320px）。配置切替後はブラウザ表示幅を再計算する。希望幅は `localStorage` の `vk-terminals.internalBrowserWidth` に保存し、狭幅による表示幅の制限や左右の開閉では上書きしない。幅を広げると保存した希望幅を現在の上限内で再び使う。

root の CSS 幅が `320px + 240px = 560px` 未満では、中央 320px と操作列を使える幅 240px を横並びにできないため、ブラウザを root 全体に重ねて表示する（全面表示）。全面表示中は背後のペインとサイドバーを `inert` にして操作対象から外し、操作列へフォーカスを移す。幅が戻って全面表示を解除すると、全面表示へ入る前にフォーカスがあった要素へ戻す。ウィンドウの最小幅は 600px のため、表示を拡大しているときに該当する。

トーストは画面左端 + 16px からアプリ内ブラウザ左端 − 16px の範囲に置き、左サイドバーの上にも重ねる。最大幅は `min(320px, calc(100vw - アプリ内ブラウザの幅 - 32px))` とし、置ける幅が 200px 未満なら案内文を折り返す。全面表示と、左サイドバーを閉じた広く表示（後述）ではブラウザの左に置ける範囲がないため、トーストを通常の右下（最大幅 `min(320px, calc(100vw - 32px))`）に出し、表示中だけページ領域の下端をトースト上端の 16px 上まで詰める。モーダル表示中はページを隠すため、これらの状態でもトーストを通常どおり左下に置く。トーストの高さが変わればその都度詰め直し、消えたらページ領域を元に戻す。トーストは全面表示中も `body` 直下に置いたままにし、モーダル表示中も操作と読み上げの対象に残す。開閉・幅変更時にペインを再フィットし、ドラッグ中はページを一時的に隠す。アプリ起動時は閉じ、タブもページも復元しない。操作列の「アプリ内ブラウザを閉じる」とタイトルバーの切替ボタンは隠すだけで、同じ起動中はタブとページを保持し、切替ボタンから再表示できる。選んでいるタブが空の新規タブのときは案内文を表示する。

### ホーム（issue #634）

再読み込みの右に家のアイコンで「ホーム」を表示する。ツールチップとアクセシブル名は「ホーム」。ページの表示前でも押せる。VK Terminals 設定の「アプリ内ブラウザ」にある「ホームページ URL」に HTTP(S) の絶対 URL を保存すると、次に押したときから同じサイドバー内で開く。

外部設定ディスクリプタで起動した場合も「アプリ内ブラウザ」から編集でき、ホームページ URL は VK Terminals 自身の設定ファイルに保存する。

空欄の場合は VK Orchestrator 設定の「作業対象リポジトリのオーナー」の先頭値（`github.owner`）を使い、`https://github.com/<owner>` を開く。設定パネルが参照する保存先を優先し、保存先の指定がない場合は `~/.vk-orchestrator/config.json` を参照する。配列と旧形式の改行区切り文字列のどちらでも空行は除外する。移動先がなければ表示中のページを保ち、未設定の案内と、設定パネルの URL 欄へ移動するボタンを操作列の下に表示する。設定ファイルを直接編集して不正な専用 URL を指定した場合も同じ案内を表示する。

### 広く表示（issue #613）

操作列の URL 入力欄の右・「外部ブラウザで開く」の左に「広く表示」ボタンを置く。アイコンは lucide の `maximize`、広く表示中は `minimize`。ツールチップと `aria-label` は同じ文言で、通常時は「ブラウザを広く表示」、広く表示中は「元の表示に戻す」。押下状態は文言の切り替えで伝え、`aria-pressed` は付けない。広く表示中は操作列のホバー色（`#21262d`）を背景に常時表示し、その状態でホバーしたときは一段明るい `#30363d` にする。ショートカットは設けない。ページ未表示でも押せる（閉じると同様に初期化時に無効化しない）。

押すと、メインエリアのグリッドに出ているペインを全部左サイドバーへ格納し、グリッドとセットアップ状況パネルを隠して、ブラウザをメインエリアの全幅で表示する。オーケストレーターのペインなど閉じる保護（`lock.close === false`）が付いたペインも格納する（ペインの「このペインを広く表示」は閉鎖保護ペインを格納しない点が異なる）。左サイドバーを開いていればサイドバーを除いた全幅、閉じていれば root の全幅にする（トースト用の 96px も残さない）。このときトーストは全面表示と同じく画面の右下に通常の幅で出し、表示中だけページ領域の下端をトースト上端の 16px 上まで詰め、消えたら元に戻す。左サイドバーを開いているときのトーストは通常の横並びと同じくブラウザの左（左サイドバーの上）に出す。ペイン用の予約幅は引かない。幅変更のドラッグ境界は隠し、矢印キーでも幅を変えない。保存済みの幅（`vk-terminals.internalBrowserWidth`）は上書きしない。左サイドバーの開閉は変えない。左右のサイドバーの併存判定と全面表示（root 幅 560px 未満）は通常時と同じ。

もう一度押すと、広く表示にしたときに格納したペインだけを元の順でグリッドへ戻し、ブラウザ幅を保存済みの幅に戻す。戻すペインの並びが広く表示前と同じときは、ペインの手動リサイズ比率（`colFr` / `rowFr`）も広く表示前の値へ戻す。ペインが閉じられた・増えたときは列数・行数が変わるため均等に戻す。押した後もフォーカスは広く表示ボタンに残す。

広く表示中に起きた操作の扱い:

- ブラウザを閉じた（操作列の × またはタイトルバーの開閉トグル。狭幅で左サイドバーを手動で開いてブラウザが閉じた場合を含む）: 広く表示を解除し、格納したペインを戻す。
- 別の URL へ移動した: 広く表示を続ける。
- 利用者がペインをグリッドへ出した（サイドバーの「→」など、格納中のペインをグリッドへ戻す操作）: 広く表示を解除して格納したペインを全部戻し、選んだペインにフォーカスを移す。
- API・自動処理でペインが追加された: 広く表示は解除せず、新しいペインはサイドバーに格納し、解除時にグリッドへ出す。API で格納指定（`stashed: true`）されたペインは解除後も格納のまま残す。新しいペインはどの経路でも同じ配置処理を通し、広く表示中に隠れたグリッドへ直接置かない。
- 使い方ガイドを開いた: 新しいペインと同じく格納したうえでグリッドへ出すため、広く表示を解除して格納したペインを全部戻し、ガイドのペインを末尾に出してフォーカスを移す。
- 格納中のペインが閉じられた: 戻す対象から外す。
- ペインの「このペインを広く表示」が使われていた: 先にそちらを解除し、単独表示を始める前の並びに組み直してから、ブラウザの広く表示に入る（単独表示中に増えたペインは末尾）。

広く表示は再起動に引き継がない（ブラウザは起動時に閉じるため）。tmux 保持役を使うときの `~/.vk-terminals/run/panes.json` には、広く表示中でも広く表示にする前の並び（格納したペインをグリッド側に戻した並び）と、広く表示前にフォーカスしていたペインを保存し、次の起動でペインが全部格納されたままにならないようにする。

モーダル表示中は WebContentsView のページだけを隠し、全て閉じると再表示する。選択メニューでは隠さない。ペイン内リンクからアプリ内で開いた後のフォーカスは元のペインへ戻す。タイトルバーから空のアプリ内ブラウザを開いた場合は URL 入力欄へフォーカスし、ページを保持したまま再表示する場合は操作元のフォーカスを維持する。トーストとリンクのツールチップはページの左側に収める（全面表示中と、左サイドバーを閉じた広く表示中のトーストは上記のとおり右下）。

### 切り替えのアニメーション（issue #629）

次の 3 つの切り替えを、利用者の操作（ボタン、ペイン内リンクからアプリ内で開く、使い方ガイドからアプリ内で開く、操作列の ×、タイトルバーの開閉トグル）のときだけ View Transitions API（`document.startViewTransition`）で動かす。状態変更と `render()` を `renderer/app.js` の `animateLayoutChange` でまとめて包む。自動処理・API によるペイン追加や配置の変化、格納中のペインをグリッドへ出す操作、狭幅で左サイドバーを手動で開いてブラウザが閉じる場合は即時のまま切り替える。設定項目は設けない。

- ペインの「このペインを広く表示」と解除: 選んだペインがグリッド内の位置からメインエリア全体へ広がり、他のペインは薄くなりながら左へ約 16px ずれて消える。左サイドバーが自動で開くときは同じ遷移の中で一緒に動く。解除は逆（戻るペインは左から 16px ずれた位置から現れる）。
- アプリ内ブラウザの開閉: ブラウザは右端から滑り込み、閉じるときは右へ抜ける。グリッドのペインは新しい位置・大きさへ移る。幅が狭くて左サイドバーが自動で閉じる場合も同じ遷移で一緒に畳む。
- ブラウザの「広く表示」と解除: ブラウザの左端が左へ伸びて全幅になり、ペインはペインの広く表示と同じく左へずれながら消える。解除は逆。

時間とイージングは `renderer/style.css` の `:root` の CSS 変数で 1 か所にまとめる。広げる・開くは 120ms・`cubic-bezier(0.2, 0, 0, 1)`（`--vktm--motion--enter-*`）、解除・閉じるは 100ms・`cubic-bezier(0.4, 0, 1, 1)`（`--vktm--motion--exit-*`）。左サイドバー単独の開閉（ハンバーガーボタンなど）のトランジションも同じ変数を使い、開くときは enter（120ms）、閉じるときは exit（100ms）で動かす。単独の開閉の後の再フィットはトランジションの終了を待ち、終了の通知が来ない場合に備えて、サイドバーに効いているトランジションの時間に 40ms を足した時点でも行う。遷移の中では左サイドバー自身のトランジションを止め、遷移側で一緒に動かす。

ペイン・左サイドバー・ブラウザの中身は伸縮させず、枠の広がりに合わせて見える範囲を変える（文字を引き伸ばさない）。切り替えの前後どちらにもある要素はクロスフェードせず、大きいほうの姿だけを不透明で出す（広がる要素は切り替え後、縮む要素は切り替え前の姿）。前後の姿が二重に写ったり、小さいほうの姿が覆わない部分が薄く透けたりしないようにするため。大きさは要素ごとに切り替えの前後で測って比べる（`renderer/app.js` の `applyLayoutTransitionImageChoice`）。名前を付けていない部分は切り替え後の姿をそのまま出す。

- ページ表示: WebContentsView は DOM の上に重なって動きに追従しないため、遷移の開始時に `internal-browser:visible` を `false` で送って隠し、ページ領域はブラウザの背景色で代用する。遷移の最中は `syncInternalBrowserLayout` が呼ばれても表示に戻さない。終わったら `syncInternalBrowserLayout` で最終の bounds を送り、表示に戻す。静止画（`capturePage`）は使わない。
- 再フィット: 遷移の最中は `fitAll` を止め、遷移が終わってから 1 回だけ合わせる。途中で PTY のリサイズを重ねない。
- 視差効果を減らす設定（`prefers-reduced-motion: reduce`）: 遷移を始めず即時に切り替え、ページ表示を隠す処理も行わない。CSS 側でも `::view-transition-*` の `animation` を `none` にする。
- `document.startViewTransition` が無い環境: 即時に切り替える。
- 遷移中の操作: ボタンは押せる（`::view-transition` は `pointer-events: none` でクリックを下の要素へ通す）。遷移中に次の操作が来たら、まだ反映していない状態変更を先に反映し、進行中の遷移を `skipTransition()` で打ち切ってから、次の状態へ即時に切り替える（最後の操作を優先）。フォーカスは遷移の開始時（状態変更の反映時）に移す。
- 打ち切り: ウィンドウのリサイズ、モーダルの表示、左サイドバー・ブラウザ・グリッドの幅のドラッグ開始時は、進行中の遷移を打ち切る。
- 左サイドバーの操作: ハンバーガーボタン・Escape キー・空のグリッドの「開く」ボタンでは、左サイドバーを開閉する前に進行中の遷移を打ち切る（まだ反映していない状態変更を先に反映するため、後から走ってブラウザの開閉を巻き戻さない）。遷移の中で左サイドバーが一緒に開閉するときは、開閉完了を待つタイマーを使わず、配置の同期と再フィットを遷移の終わりの 1 回にまとめる。
- ペインの並びを変える処理（ペインの追加・閉じる・移動・格納・グリッドへ戻す・格納エリア内の移動）は、API・自動処理から呼ばれた場合も含め、入口でまだ反映していない遷移の状態変更を先に反映する。遷移そのものは止めない。

## 保存領域と安全性

WebContentsView は `persist:vk-terminals-internal-browser` を使用し、ターミナル側と Cookie を分ける。単体版と同梱版の保存場所も分かれる。`sandbox: true`、`nodeIntegration: false`、`contextIsolation: true`、`webSecurity: true`、`allowRunningInsecureContent: false`。preload は渡さない。通常の開く URL は HTTP(S) のみ。組み込みの案内ページだけ `vk-terminals-help://guide/` をページ遷移・リダイレクト・新規ウィンドウ要求の例外として受け付ける。クエリ・別パス・別ファイル・`file:` は拒否し、ハッシュだけを許可する。専用プロトコルは特権スキーム登録を使わず、登録済み `help.documentPath` の HTML のみを返す。実体パスと一致しないリンクは拒否し、`O_NOFOLLOW` で開いた同じ fd から読む。応答には `Content-Security-Policy: frame-ancestors 'none'` と `X-Content-Type-Options: nosniff` を付ける。不正なアドレスや読み込み失敗はネットワークエラーとして扱う。案内ページ内の HTTPS リンクは同じサイドバーへ移動し、戻る操作で案内へ戻る。戻る・進むは Electron の履歴に従う。案内からリンク先へ進んだ後は、戻るで案内に戻り、さらに戻ると案内より前のページへ戻る。進むでリンク先へ再度進める。案内ページで外部ブラウザを選ぶと main 側が登録済み HTML の file URL と現在のハッシュを組み立てる。外部ブラウザで開けなければ再試行を促す通知を表示する。新規ウィンドウは作らず、同じサイドバーの新しいタブに開く（後述「タブ」）。専用セッションの権限要求は全て拒否する。証明書エラーの回避は設けない。IPC の送信元と座標を検証する。終了と再起動で WebContentsView を破棄する。

ログイン状態は再起動後も保持するが、外部ブラウザのログインは引き継がない。ログアウトは GitHub 上で行う。パスワードと認証アプリのコード、GitHub Mobile 承認、パスキー、企業 SSO の実機確認結果は未確認（PR で記録）。

モバイル表示、開閉ショートカットは対象外。

## 内部の作り（issue #643）

タブ対応（issue #601）の準備として、`utils/internalBrowser.js` を 2 層に分ける（この時点では画面に見えるタブは常に 1 つ。タブの UI と動きは issue #644 で入れた。後述「タブ」）。

- タブ 1 つ分（`createBrowserTab`）: WebContentsView 1 つと、URL・戻る / 進むの可否・読み込み中・エラー・GitHub の 404 案内・ダウンロード停止案内などの状態、CDP による遷移の追跡を持つ。
- タブ全体（`createInternalBrowser`）: タブの一覧・選んでいるタブ・表示位置・表示可否・モーダル数を持つ。画面に付けるのは選んでいるタブの WebContentsView だけ。セッション単位の権限・リクエスト・ダウンロードの検査はここで 1 回だけ設定する。ダウンロードは配送元のページからタブを特定し、分からないときは URL が一致する操作を持つタブ（1 つに絞れなければ選んでいるタブ）へ振り分ける。
- IPC: `internal-browser:open` / `internal-browser:action` / `internal-browser:external` は末尾に省略可能な `tabId` を受け、省略時は選んでいるタブを対象にする。不正・未知の番号は受け付けない。`internal-browser:state` と `internal-browser:download-blocked` には `tabId` と、選んでいるタブかどうか（`active`）を載せ、画面は `active: false` の通知を表示に使わない。
- 古い通知を捨てる判定に使う `navigationOperationId` は、タブ全体で 1 つの通し番号にする。

## タブ（issue #644）

承認済みの仕様: https://github.com/vektor-inc/vk-terminals/issues/601#issuecomment-7017570477 （回答の記録: https://github.com/vektor-inc/vk-terminals/issues/601#issuecomment-7018108651 ）。

### 表示の仕組みとタブごとの状態

- タブ 1 つごとに WebContentsView を 1 つ作る。画面に付けるのは選んでいるタブのものだけで、切り替えるときに `addChildView` / `removeChildView` で付け替える。表示していないタブを休ませる仕組み（破棄して選んだときに読み直す）は入れない。
- タブごとに URL、戻る / 進むの可否、読み込み中、読み込みエラー、GitHub の 404 案内、ダウンロードを止めたときの案内、ページタイトル、ファビコンを持つ。画面側は表示しているタブの操作列・お知らせの状態（URL 欄の未送信の入力、読み込み中の表示、入力欄の下の案内、ホーム未設定の案内、閉じた GitHub の 404 案内、上限の案内）をタブごとに退避・復元する。
- タブを切り替えると、ページと、戻る / 進む・URL 欄・お知らせ・エラー表示がそのタブのものに入れ替わる。タブを選んだときに main が送り直す状態には `selected: true` を付け、画面は退避しておいた読み込み中の記録よりこの状態を正として扱う（後ろにいる間に読み込みが終わった・置き換わった・失敗した場合も、URL 欄と操作列を今のページに揃える。未送信の入力は別に持ち、上書きしない）。後ろのタブで起きたお知らせ（ダウンロードを止めた案内、読み込み結果の読み上げ、上限の案内）は、そのタブを選んだときに出す。読み込み結果（完了・中止・置き換え）は、そのタブでまだ読み上げていない操作のものだけを、選んだときに 1 回だけ読み上げる。表示している間に結果まで届いた操作は読み上げ済みとして扱い、選び直しても繰り返さない。
- タブの一覧と選んでいるタブは main が持つ。main はタブの一覧（`internal-browser:tabs`。並び順、タイトル、ファビコン、読み込み中、空の新規タブか）を状態の通知より先に送り、画面はこの通知で表示するタブを切り替える。操作列の操作と URL 欄の Enter は、表示しているタブの番号を添えて送る。

### タブの行

- 操作列の上に高さ 32px のタブの行を置く（Chrome と同じ並び）。各タブにページタイトル（無ければホスト名、空の新規タブは「新しいタブ」）、ファビコン、閉じる × を出す。読み込み中はファビコンの位置に回転する印を出す（視差効果を減らす設定では回転しない）。ファビコンが無いページは地球のアイコンを出す。
- タブの幅は最大 180px で、入りきらないときは等分に縮める。幅が 72px 未満になったタブは文字を隠し、選んでいないタブはファビコンだけ（36px）まで縮む。選んでいるタブはファビコンと × が残る 60px までにとどめる。それでも入らなければタブの行だけ横スクロールする（スクロールバーは出さず、縦方向のホイールでも横に動く）。選び直したタブは見える位置までスクロールする。
- 「＋」（新しいタブ）は右端に固定し、操作列のボタンと同じ見た目にする。
- 選んでいるタブは、操作列と同じ背景色（`#0d1117`）・上端の青い線（`#58a6ff`。読み込み中の帯と同じ色）・明るい文字の 3 つで示す（色だけに頼らない）。タブの行の地は `#010409`、選んでいないタブの文字は `#8b949e`。
- 中クリックでタブを閉じる。ドラッグでの並べ替えは入れない。

### 開き方

- 「＋」: 空の新しいタブを末尾に開いて選び、URL 欄にフォーカスを置く。空の新規タブには「上の入力欄に URL または検索語を入力して Enter を押すと、ここに表示されます。」を出し、ホームを開けるとき（ホームページ URL か `github.owner` が設定されているとき）だけ「ホームを開く」ボタンを添える。
- ページ内の「新しいタブで開く」リンク（`target="_blank"`）と `window.open`: 押したタブのすぐ右に新しいタブを開いて前に出す。Cmd（Windows・Linux は Ctrl）を押しながらのクリック（Electron の disposition が `background-tab`）は後ろに開く。HTTP(S) と組み込みの案内ページ以外は開かない。
- ペインの URL・issue タイトル・PR ボタンの「アプリ内で開く」: 同じ URL のタブがあればそのタブに切り替え、読み込み直さない（スクロール位置などが残る）。同じ URL かは、各タブを代表する URL（読み込み中なら読み込み先、失敗なら失敗先、それ以外は表示中の URL。タブの行に出す URL と同じ）だけを、パスの末尾の `/` と `#` 以降を無視して比べる（検索条件・ホスト・ポート・スキームが違えば別のページ）。複数あれば選んでいるタブ、無ければ左のタブを優先する。無ければ、選んでいるタブが空の新規タブならそのタブに開き、そうでなければ新しいタブを末尾に開いて前に出す。
- URL 欄の Enter とホームボタン: 今のタブに開く。
- 使い方ガイド（設定の「ヘルプ」から開く案内ページ）: 今のタブに開く（タブ化前と同じ）。

### タブの数の上限

- 開けるタブは 10 個まで。上限では「＋」を押せない状態にし、ツールチップを「新しいタブ（タブは 10 個まで開けます）」にする。
- ページやペインから開こうとして上限に当たったときは新しいタブを開かず、お知らせ欄に「タブは 10 個まで開けます。使わないタブを閉じてから、もう一度開いてください。」と「外部ブラウザで開く」（開こうとした URL を開く）・「案内を閉じる」を出し、読み上げる。案内はタブを閉じて上限を下回ると消す。黙って古いタブを閉じたり、今のタブに開いたりはしない。

### 閉じる

- タブの × は、そのタブのページを捨てる。選んでいるタブを閉じたときは右隣、右が無ければ左隣を選ぶ。
- 最後の 1 タブを閉じたら、サイドバーごと閉じ、フォーカスをツールバーのアプリ内ブラウザ切り替えボタンに戻す。次に開いたときは空の新しいタブ 1 つから始まる。
- 操作列の ✕ は「アプリ内ブラウザを閉じる」（タブの × と区別する）。隠すだけでタブは残す。
- macOS の ⌘ + W（issue #649）は、ページを操作しているときはそのタブを、タブの行・操作列などサイドバーの中にフォーカスがあるときは表示中のタブを閉じる。閉じ方（次に選ぶタブ・最後の 1 タブでサイドバーごと閉じる）はタブの × と同じ。最後の 1 タブでもウィンドウは閉じない。ページで押して閉じたときは、続けて押せるよう次に選んだタブのページへフォーカスを移す。作業ペインなどサイドバーの外では何もしない。押し続けたときの繰り返し入力では閉じない。
- ⌘ + W はウィンドウと各タブのページの `before-input-event` で止める（`preventDefault`）。メニューのアクセラレータより先に届く段階のため、組み込み元のメニューに「ウィンドウを閉じる」（⌘ + W）が残っていてもウィンドウは閉じない。画面へは main から `app:close-shortcut`（`{ tabId }`。ページで押したときはそのタブの番号、それ以外は `null`）で知らせ、閉じる処理は画面がタブの × と同じ経路（`internal-browser:tab-close`）で行う。Windows・Linux の Ctrl + W はターミナルの「直前の単語を消す」入力と重なるため扱わない。
- 「広く表示」と「アプリ内ブラウザを閉じる」は操作列の右端に残す。design-rules の「情報のまとまり」では、サイドバー全体の表示操作が選んでいるタブの操作列に混ざる点が違反になるが、既存のボタンの位置を動かさずに済み、タブを並べられる幅も減らないため、承認済みの例外とする（https://github.com/vektor-inc/vk-terminals/issues/601#issuecomment-7017570477 の質問 4、案1）。

### アクセシビリティ

- タブの行は `role="tablist"`（「アプリ内ブラウザのタブ」）、各タブは `role="tab"` と `aria-selected`。読み込み中はタブの名前に「（読み込み中）」を添える。
- Tab キーで止まるのは選んでいるタブだけ（他は `tabindex="-1"`）。タブ同士は ← → で移り（端では反対の端へ）、Home / End で先頭・末尾へ移る。Enter / Space で切り替える（フォーカスの移動だけでは切り替えない）。フォーカスのあるタブで Delete キーを押すと閉じる（`aria-keyshortcuts="Delete"`）。タブの × はマウス操作用で、読み上げ対象とキーボードのフォーカス対象から外す。
- 開いた（「新しいタブを開きました」「新しいタブを後ろに開きました」）・閉じた（「タブを閉じました」）・上限に達したことを、タブの行の下の読み上げ専用の領域で読み上げる。開いてタブの数が上限に達したときは「新しいタブを開きました。タブは 10 個まで開けます。」のように続けて読み上げる（「＋」が押せなくなり Tab キーでも止まらなくなるため）。
- タブの行を描き直すときは、並びが変わった要素だけを差し込み、変わっていない属性は書き直さない（フォーカスを保ち、同じタブを読み直させない）。
- 閉じたタブにフォーカスがあったときは、次に選んだタブへフォーカスを移す。

### ファビコン

画面の読み込み制限（CSP の `img-src 'self' data:`）を広げず、main が取得して data URL に変えてから画面へ渡す（`utils/internalBrowserFavicon.js`）。取得はアプリ内ブラウザのセッションを使わず、Node の HTTP(S) で行う（接続先のアドレスを確かめるため）。

- 取得するのは、ページが知らせた候補のうち先頭の HTTP(S) の URL（URL に認証情報を含むものは除く）。端末・社内ネットワーク側の宛先は、ページ自身が同じホストにあるときだけ取得する。宛先はホスト名と、名前解決した後のアドレスの両方で確かめ、確かめたアドレスに接続する。リダイレクトは自分でたどり、送る前に毎回同じ条件で確かめる（5 回まで）。Cookie などの認証情報は送らない。
- 社内ネットワークのサイトでも、ホスト名が外部の名前で内側のアドレスを返すものは、ファビコンを取得しない（タブには地球のアイコンを出す）。
- 途中で断った応答も含め、終わり方によらず通信を打ち切る。
- 大きさは 64KB まで（宣言の長さと、読んだ本文の両方で打ち切る）。待ち時間は 5 秒まで。
- 画像の種類は先頭のバイトで判定する（PNG・ICO・GIF・JPEG・WebP）。SVG はサーバーが SVG と宣言し、本文が SVG のときだけ受け付ける。画像でない応答は捨てる。
- 取得結果は 64 件まで覚え、同じアイコンは取得し直さない（失敗したものは覚えない）。取得中に別のアイコンへ替わったら古い結果は使わない。別の文書へ移ったらタイトルとファビコンを消す。
- 画面は `data:image/` で始まる値だけを表示する。

### ログイン

GitHub のログイン（github.com/login からのフォーム送信と、ログイン後の戻り先への移動）は同じタブの中の遷移なので、タブ化の影響を受けない。`window.open` で開いた画面から元のページへ結果を返す方式のログイン（ポップアップ）は、新しいタブで開いても元のページとつながらないため動かない（タブ化前も同じ表示に読み込み直していたため、退行ではない）。

### 入れないもの

- キーボードのショートカット（Cmd+T / Ctrl+Tab と、Windows・Linux の Ctrl+W）。Windows では Ctrl+W・Ctrl+T がターミナルの入力と重なるため。macOS の Cmd+W は「閉じる」に書いたとおりタブを閉じる（issue #649）。
- アプリ再起動時のタブの復元。
- 表示していないタブを休ませる仕組み。
- ドラッグでの並べ替え。

### IPC

- renderer → main（応答あり）: `internal-browser:get-tabs`（起動時のタブ一覧）、`internal-browser:tab-new`、`internal-browser:tab-select`、`internal-browser:tab-close`（最後の 1 つなら `{ closedLast: true }`）、`internal-browser:open-tab`（「アプリ内で開く」。`{ result: 'switched' | 'opened' | 'limit', tabId }`）、`internal-browser:home-available`。タブ番号の検証は `utils/internalBrowser.js` で行い、不正・未知の番号は受け付けない。
- main → renderer: `internal-browser:tabs`（`{ tabs, activeTabId, maxTabs }`。前回と同じ内容なら送らない）、`internal-browser:tab-limit`（ページの新しいタブ要求が上限に当たったタブと URL）、`app:close-shortcut`（⌘ + W。上の「閉じる」）。

## レビュー後の決定

ページが離脱を阻止したときは、メインウィンドウを親に、メッセージ「このページを離れますか？」の確認を出す（Windows・Linux のタイトルも同じ）。詳細文は「入力中の内容は保存されない可能性があります。」、操作は「移動する」「このページにとどまる」とし、既定・キャンセルは「とどまる」。移動を選んだときだけ離脱を許す。

メニュー表示中に矢印・Home・End・Enter・Space・Esc・Tab 以外のキーを押したときは、メニューを閉じて元のペインの端末へフォーカスを戻す。キーは端末へ送らない。Shift・Alt・Meta・Control 単独と日本語入力の変換中は閉じずに無視する。初期フォーカスは「アプリ内で開く」。

アプリ内ブラウザのダウンロード要求は取り消す。Enter で開こうとした URL と一致するときだけ、その URL を操作列の外部ブラウザボタンの対象に設定してから「ダウンロードはできません。操作列の「外部ブラウザで開く」から行ってください。」とトーストを出す。一致しないときは操作列の対象を変えず、「ダウンロードはできません。外部ブラウザでダウンロードしてください。」と案内する。ダウンロード阻止の読み上げは通常トーストに集約する。持続トーストが表示中で新しいトーストを出せない場合だけ、持続表示を保ったままアプリ内ブラウザの live status で同じ結果と回復操作を読み上げる。
