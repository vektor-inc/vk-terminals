# アプリ内ブラウザ仕様（issue #590）

## クリック操作

ペイン内 URL、issue タイトル、PR ボタンをクリックするとリンクのそばに「アプリ内で開く」「外部ブラウザで開く ↗」のメニューを出す。開き先を選ぶまではページを開かない。未フォーカスのペインでも最初のクリックで表示する。ペイン内 URL は既存の `terminalLinkClickMode` が `click` なら通常クリック、`modifier` なら ⌘ / Ctrl+クリックでメニューを出す。タイトルと PR は設定に関係なく通常クリックで表示する。修飾キーによる直接起動と新しい設定項目は設けない。

Claude Code と Codex のペイン内 URL は、文字列から検出したリンクと端末の OSC 8 リンクのどちらも同じクリック判定と開き先メニューを使う。

ドラッグ、右クリック、中クリック、ダブルクリックの 2 回目では表示しない。Esc、Tab、外側クリック、ペインのホイールで閉じ、上下矢印で移動し Enter / Space で決定する。メニューは `role=menu` / `menuitem`。ペイン内 URL はクリック位置の右下、タイトルと PR は要素の左下に置き、画面端とサイドバー左端を超えない。初期フォーカスは「アプリ内で開く」。閉じたら元のペインまたは要素にフォーカスを戻す。

## 右サイドバー

右側に 1 枚を使い回し、新しいリンクはページを差し替える。上部の操作は戻る、進む、再読み込み、URL 入力欄、外部ブラウザで開く、閉じる。URL 入力欄へ URL または検索語を入力し、Enter でページを開く。URL のコピー操作は設けない。読み込み中は進行バー、失敗時は失敗先のホスト名と再読み込み・外部ブラウザで開く操作を表示し、後続の読み込み状態通知でも保持する。次の遷移で消す。失敗表示の外部ブラウザ操作は読み込みに失敗した URL を開き、操作列の URL は確定した URL のみを表示する。外部ブラウザで開く前に URL を検証する。github.com の 404 ではプライベートリポジトリへのログイン案内と「GitHub にログイン」「閉じる」を表示し、次の遷移まで保持する。

幅は左端のドラッグまたは矢印キーで変更する。下限 360px、既定は左サイドバーと横並び要素の最小幅を除いた幅の 45%（480〜720px）。アプリ内ブラウザを表示しているときは、左サイドバーを除いた幅に「ブラウザ下限 360px ＋ 横並びのペイン予約幅 `max(.grid の横並び時の最小幅, 320px, 列数 × 272px)` ＋ パネル最小幅 240px」が収まらない場合だけ、セットアップ状況パネルを帯に畳む。ブラウザを閉じるとウィンドウ幅 1000px 未満で畳む判定に戻る。帯の「開く」は既存の影つき重ね表示を使う。帯に畳んだ後、またはパネルがないときは横並び用の予約幅を引かず、実際の `.grid` の最小幅（通常 12px）を使う。ブラウザの上限は `min(max(0, 使用可能幅 − グリッド最小幅), max(360px, 使用可能幅 − max(グリッド最小幅, 320px, 列数 × 272px)), ウィンドウ全体の CSS 幅 − 96px)`。ペイン領域が足りないときはブラウザの下限 360px を優先する。360px 未満になるのは、左サイドバーを閉じて CSS 幅が 456px 未満の場合、または左サイドバーを除いた幅が 372px 未満（グリッド最小幅 12px ＋ 360px）の場合だけ。配置切替後はブラウザ幅を再計算する。トーストは画面左端 + 16px からアプリ内ブラウザ左端 − 16px の範囲に置き、左サイドバーの上にも重ねる。最大幅は `min(320px, calc(100vw - アプリ内ブラウザの幅 - 32px))` とし、置ける幅が 200px 未満なら案内文を折り返す。`localStorage` の `vk-terminals.internalBrowserWidth` に保存する。開閉・幅変更時にペインを再フィットし、ドラッグ中はページを一時的に隠す。アプリ起動時は閉じ、ページは復元しない。閉じても同じ起動中はページを保持し、タイトルバーの切替ボタンから再表示できる。未表示のときは案内文を表示する。

モーダル表示中は WebContentsView のページだけを隠し、全て閉じると再表示する。選択メニューでは隠さない。ペイン内リンクからアプリ内で開いた後のフォーカスは元のペインへ戻す。タイトルバーから空のアプリ内ブラウザを開いた場合は URL 入力欄へフォーカスし、ページを保持したまま再表示する場合は操作元のフォーカスを維持する。トーストとリンクのツールチップはページの左側に収める。

## 保存領域と安全性

WebContentsView は `persist:vk-terminals-internal-browser` を使用し、ターミナル側と Cookie を分ける。単体版と同梱版の保存場所も分かれる。`sandbox: true`、`nodeIntegration: false`、`contextIsolation: true`、`webSecurity: true`、`allowRunningInsecureContent: false`。preload は渡さない。開く URL、ページ遷移、リダイレクト、新規ウィンドウ要求は HTTP(S) のみ。新規ウィンドウは作らず同じサイドバーに開く。専用セッションの権限要求は全て拒否する。証明書エラーの回避は設けない。IPC の送信元と座標を検証する。終了と再起動で WebContentsView を破棄する。

ログイン状態は再起動後も保持するが、外部ブラウザのログインは引き継がない。ログアウトは GitHub 上で行う。パスワードと認証アプリのコード、GitHub Mobile 承認、パスキー、企業 SSO の実機確認結果は未確認（PR で記録）。

モバイル表示、開閉ショートカットは対象外。

## レビュー後の決定

ページが離脱を阻止したときは、メインウィンドウを親に、メッセージ「このページを離れますか？」の確認を出す（Windows・Linux のタイトルも同じ）。詳細文は「入力中の内容は保存されない可能性があります。」、操作は「移動する」「このページにとどまる」とし、既定・キャンセルは「とどまる」。移動を選んだときだけ離脱を許す。

メニュー表示中に矢印・Home・End・Enter・Space・Esc・Tab 以外のキーを押したときは、メニューを閉じて元のペインの端末へフォーカスを戻す。キーは端末へ送らない。Shift・Alt・Meta・Control 単独と日本語入力の変換中は閉じずに無視する。初期フォーカスは「アプリ内で開く」。

アプリ内ブラウザのダウンロード要求は取り消す。Enter で開こうとした URL と一致するときだけ、その URL を操作列の外部ブラウザボタンの対象に設定してから「ダウンロードはできません。操作列の「外部ブラウザで開く」から行ってください。」とトーストを出す。一致しないときは操作列の対象を変えず、「ダウンロードはできません。外部ブラウザでダウンロードしてください。」と案内する。ダウンロード阻止の読み上げはトーストに集約する。
