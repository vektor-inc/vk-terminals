# 組み込み起動のセットアップ専用シェル（#607）

`embedded.start({ setupShell: { command, cwd? } })` で最初のペインを素のシェルとして開く。`setupPane` は Claude Code のスキル起動用なので別のオプションにする。`cwd` は実在する絶対ディレクトリ、省略時はホーム。`command` は空でない 1000 文字以下の単一行で、制御文字、書式制御文字、行・段落区切りを許さない。

シェルのプロンプト出力を待ち、コマンドを PTY の入力欄へ書く。シェルがブラケット貼り付けを有効にした場合はその形式を使う。未対応シェルでは通常の入力とする。入力受付はブラケット貼り付け開始を主に、行末記号を予備に検出し、150ms 出力が静まってから書く。30秒で検出できなければ監視を終了する。Enter は送らず、利用者が内容を確認して実行する。プロンプトが確認できない場合も盲打ちしない。

この起動ではセッション全体で保持役を使わず、前回ペインの復元、セットアップ状況の起動時確認・自動表示、設定済み追加ペインの作成、エージェントの自動起動、初期コマンドの自動送信を行わない。最初の専用ペインだけにコマンドを一度入力する。2枚目以降と再初期化後のペインはエージェントを起動せず、初期コマンドも送らない素のシェルにする。専用ペインは node-pty でログインシェルとして起動する。入力済みの行へエージェント再起動や `/api/send` などが Enter 付き文字列を書き込むと、つながった行が実行されうる（入力欄に置く方式の性質）。通常の起動と `setupShell` を渡さない組み込み起動は従来の経路を使う。起動引数・環境変数・HTTP API にこの指定口は作らない。
