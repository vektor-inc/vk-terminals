# tmux ペイン保持役（issue #585）

## 起動

組み込み起動では `paneHolder: 'tmux'` とともに `tmuxPath` に実行可能な通常ファイルの絶対パスを指定できる。シンボリックリンクは不可。指定すると版確認、制御接続、コマンド、停止処理に同じファイルを使い、PATH で探し直さない。`tmuxEnv` は `TERMINFO` と `TERMINFO_DIRS` の文字列だけを tmux サーバー環境に追加できる。`tmuxPath`・`verifyPaneHolder`・`paneHolderWarning`・`paneHolderFallback`・`onPaneHolderError`・`tmuxEnv` は `paneHolder: 'tmux'` とともに指定する。NUL・改行を含む値は不可。

`verifyPaneHolder(info)` は同期関数で、既存保持役へ制御接続する直前に `{ stage: 'attach', tmuxPath, socket, paneId: null }`、各ペインを復元する直前に `{ stage: 'restore', tmuxPath, socket, paneId }` を渡す。`true` 以外の戻り値と例外は失敗とし、対象ペインは接続しない。確認失敗は `paneHolderWarning`（既定は「前回のペインを確認できなかったため、表示していません。ペインは裏で動いたままです。」）で操作を止めない通知を出す。attach 段階・restore 段階のどちらで失敗しても、その起動中は新しいペインを tmux にも node-pty にも作らない。確認失敗または `paneHolderFallback: 'error'` によって新規作成を止めたとき、作成エラーに目印を付けて画面へ伝える。全ペインが拒否された場合も空の画面に警告と終了案内を表示する。警告は閉じるまで表示し、通常の通知で上書きしない。目印のない作成失敗は通常のエラー処理に戻す。

保持役の初期化またはペイン作成に失敗したときの `paneHolderFallback` は `'node-pty'`（既定）または `'error'`。`'error'` では切り替えず、`onPaneHolderError({ reason, socket })` を呼んでペイン作成を失敗として扱う。`'error'` の失敗では元の理由を保持し、アプリを再起動するまで新しいペインの作成を止める。確認失敗では `paneHolderFallback` の値にかかわらず作成を止める。確認関数と失敗通知関数は既存の同期処理に合わせて同期で呼ぶ。

`--pane-holder=tmux` または `embedded.start({ paneHolder: 'tmux' })` で有効になる。未指定・不正な CLI 値は node-pty を使う。組み込みオプションの不正値は例外にする。設定画面の項目には加えない。tmux 3.0 未満、バージョン不明、その他の保持役の初期化失敗時は、原因とソケットのパスを一度だけ警告し、そのアプリの起動中は再試行せず node-pty を使う。制御モードの接続が後から落ちた場合は、次のペイン作成時に保持役を作り直す。

## 構成

アプリごとに tmux 制御モードのクライアントを 1 本持つ。`%output` の 8 進エスケープをバイト列へ戻し、既存の `onData` 処理へ渡す。入力は制御クライアントの標準入力へ分割した `send-keys -H`、サイズ変更は `resize-window`。制御応答は送信した命令ごとに FIFO で対応付け、接続直後の応答は命令の応答に数えない。各ペインの `#{pane_pid}` をシェル PID として使う。画面の端末問い合わせへの応答は tmux に重複送信しない。Claude Code / Codex の起動コマンドからだけ `TMUX` と `TMUX_PANE` を外す。

制御モードの初期セッションには保持役用の `sleep` ペインを置く。アプリ終了時は制御クライアントだけを切断し、tmux のシェルは動かし続ける。個別のペインを閉じると、そのシェルを止める。保持役ごと止める `stopHolder` は本人専用ソケットを検査し、`-S` を指定して `kill-server` を実行する。ソケットが無い場合や検査に失敗した場合は何もしない。組み込み側は `stopHolder` に `tmuxPath` と環境を必ず渡す。

## 環境とソケット

tmux サーバーの環境には、値のある `HOME`, `USER`, `LOGNAME`, `SHELL`, `PATH`, `TMPDIR`, `LANG`, `LC_ALL`, `LC_CTYPE`, `LC_MESSAGES`, `TERMINFO`, `TERMINFO_DIRS` だけを渡す。同梱の `tmux-holder.conf` を `-f` で指定し、利用者の設定は読まない。

ペインは本人だけが読める 0600 の一時スクリプトに環境変数を書き、`env -i /bin/sh` で実行する。変数一覧は `buildPtyEnv(process.env)` が作る変数と `TERM=xterm-256color`。シェルが代入できない予約名と不正な名前は警告して除外する。スクリプトはシェル起動前に削除され、最後は `exec` で対象シェルに置き換わる。値はプロセス引数に載らない。シェルには追加引数を付けない。alias や関数で定義した `claude` / `codex` は、この起動経路では使われない。

専用ソケットは既定で `~/.vk-terminals/run/tmux.sock`。テスト時は `VK_TERMINALS_HOLDER_RUN_DIR` で親フォルダを変更できる。親フォルダは本人所有の 0700、ソケットは本人所有の実ソケットで 0600 または tmux が接続中に設定する 0700 とする。シンボリックリンクを拒否する。ソケットパスが 104 バイト以上なら起動前に失敗する。残ったソケットは起動時にサーバー応答を確認し、停止済みなら残留ソケットを回収する。保持役セッションに接続中の別クライアントがいれば使用しない。すべての tmux 呼び出しに `-S` を付ける。手動で片付ける場合はアプリと保持役が停止したことを確認し、`~/.vk-terminals/run/tmux.sock` と `~/.vk-terminals/run/tmux.lock` を削除する。

## 再接続と画面状態

次の起動では専用ソケットを検査し、既存の保持役へ制御モードで接続する。生きているペインを tmux の ID と `@vk_term_id` で照合し、終了済みのペインを除外する。ペイン番号は最大の `@vk_term_id` の次から採番する。Claude Code のペインでは、保存した合言葉で裏の作業の通知の受け口を作り直し、ペインのシェルの PID からエージェントの実行状態を作り直す（`docs/specification-background-work.md` の「保持役を使うときの再起動（#587）」）。それ以外のペインでは、エージェントを再起動するまでエージェントの実行状態は不明として扱う。復元したペインでは新しいシェル、エンジンの起動コマンド、初回コマンド、信頼確認への自動応答を実行しない。復元したペインがあれば初期ペインと設定の追加ペインも作らない。

画面の順番、格納中の順番、最後に選んだペイン、名前、エンジン、PR ボタンの URL と状態は `~/.vk-terminals/run/panes.json` に保存する。`states.json` は利用しない。ファイルは本人所有の 0600 とし、原子的に置換する。読み直す際は親フォルダ、ソケット、ファイルの所有者、権限、シンボリックリンクを検査する。検査を通らないメタデータは使わず、tmux 側で確認できたペイン番号から既定名で復元する。保存後に増えた生存ペインも既定名で末尾へ加える。保持役を使わない起動ではメタデータに触れない。

履歴は tmux の 10,000 行までとし、画面側の xterm.js と揃える。`capture-pane -e -S -` で履歴を取得し、制御モードの `%end` を境に、それ以前のライブ出力を重複として捨てる。画面側の行列数へ tmux ペインを合わせてから履歴を取得し、続けて同じ制御接続から取得した入力モードとカーソル位置を復元し、後続のライブ出力を流す。再生が終わるまで入力は保留する。履歴とライブ出力の間に案内行は加えない。復元できなかった記録がある場合だけ、一度通知する。件数が分からない場合は件数を示さない。生存ペインを既定名で戻せた場合は、名前と順番を戻せなかったことを通知する。保持役が無く古い記録だけがある場合は件数を通知しない。
