# セットアップ状況の一覧（vk-terminals#456）

VK Orchestrator のアプリ（VK Terminals を部品として組み込んだもの）で、セットアップが済んでいないときに、足りないものの一覧と「セットアップを始める」ボタンを画面に出す仕様です。

- issue: https://github.com/vektor-inc/vk-terminals/issues/456
- 承認済みの仕様提案: https://github.com/vektor-inc/vk-terminals/issues/456#issuecomment-6315128406
- 承認の記録（3 項目すべて推奨案）: https://github.com/vektor-inc/vk-terminals/issues/456#issuecomment-6316685339
- 承認後はこのファイルを正とします。仕様を変えるときはこのファイルと実装を一緒に直します。

## 承認された 3 つの判断

1. vk-orchestrator 側で必要な変更（導入用コマンドの欄・理由の欄・gh が入っているかの項目）は、別のサブ issue（vektor-inc/vk-orchestrator#646）で別の PR にする。この issue の PR は vk-terminals 側だけを作り、**欄が届けば表示する作り**にする。
2. 一覧は、ペインの右に並べるパネルに出す。「閉じる」で上端の 1 行の帯に畳む（完全には消さない）。
3. 初回の自動オープンは、このパソコンで初めて「未完了」と判定されたときの 1 回だけ。2 回目以降は「セットアップを始める」ボタンだけにする。

## 登場するものと関係

- VK Orchestrator（アプリの本体側）: `doctor --json`（設定がそろっているかを判定する診断コマンド）を持つ。判定の正はこちら。
- VK Terminals（このリポジトリ）: 受け取った結果を表示するだけで、判定はしない。`doctor` を自分で起動しない。

## 組み込み用の入口（embedded.start のオプション）

`embedded.start()` に次の 2 つを足す。**必ず対で渡す**（片方だけだと起動時に例外）。どちらも渡さなければ一覧は出ない。

- `getSetupStatus`: `doctor` の結果 `{ requirements, summary }` を返す非同期関数。引数に `{ signal }`（20 秒で abort される）を渡す。別プロセスで動かすかは組み込み側が決める（画面を固めないため）。
- `setupPane`: `{ cwd, prompt }`。
  - `cwd`: セットアップ用ペインの作業フォルダ。**実在する絶対パス**のみ受け付ける。
  - `prompt`: 最初のプロンプト。`/^\/[a-z0-9-]+$/` に一致するものだけ（例 `/vk-orchestrator-setup`）。
  - 作業フォルダとスキル名は vk-orchestrator の持ち物（vk-orchestrator#640 の範囲）なので、組み込み側から渡す。

検証は `utils/runtimeOptions.js`（`normalizeEmbeddedOptions`）。

採らなかった案: 実行ファイルと引数を受け取る案（Node 不要の起動経路 vk-orchestrator#639 と食い違う）／`doctor` の結果をファイルに書き出して読む案（「もう一度確認」で再実行を頼む口がどのみち要り、古い結果を出す危険がある）。

### 組み込みオプションが無いとき（`electron .`・zip 版）

上の 2 つが無いときは、**IPC（`setup:*`）も画面の部品も作らず、今と同じ画面のまま**にする（vk-orchestrator 側の既存の案内・自動投入と二重にしないため）。

- main.js: `SETUP_FEATURE` が `null` のとき `setup:check` / `setup:initial-pane` のハンドラを登録しない。`app:get-config` に `setupPanelEnabled` を足さない。`terminal:create` の `setupPane` は例外にする。
- renderer: `setupPanelEnabled === true` のときだけパネルの制御部（`renderer/setupPanel.js`）を生成する。
- テスト: `tests/setupWiring.test.js`（静的チェック）、`tests/e2e/setup-status-panel.smoke.spec.js` の最後のケース（実機で受け口・画面の要素・文言が無いことを確認）。

## doctor の結果の扱い

`doctor --json` の出力は `{ requirements, summary }`。

- 各項目: `id` / `group` / `label` / `required` / `ok` / `current` / `hint` / `target`。
- `summary`: `total` / `okCount` / `requiredCount` / `requiredOkCount` / `missingRequired` / `allRequiredOk`。

### vk-orchestrator#646 で足される欄

欄が**あれば**使い、**無ければ**出さない。説明文（`hint`）からコマンドを抜き出したり、理由を推測したりはしない。

- `commands: [{ command, os }]`: 導入用コマンド。あればコマンド枠とコピーボタンを出す。無ければ説明文（`hint`）だけ。
- `reason: 'not-installed' | 'not-on-path' | 'not-authenticated'`: 未充足の理由。あれば状態の文言を出す。無ければ出さない。
  - `not-installed` → 「入っていません」
  - `not-on-path` → 「入っていますが、見つかりません」＋補足「アプリを終了して開き直してください。それでも同じなら、入れた場所を確かめてください。」
  - `not-authenticated` → 「まだ認証していません」

### 正規化（`utils/setupStatus.js` の `normalizeSetupStatus`）

組み込み側が返した値は外から来た値として扱う。main で正規化してから画面へ渡す。

- 形が不正なもの（配列でない・`summary.allRequiredOk` が真偽値でない・項目に `id` / `label` / `ok` が無い）は「確認できませんでした」扱い。**セットアップ済みの扱いには倒さない**。
- `summary.allRequiredOk` と項目の必須・充足が食い違うときも「確認できませんでした」扱い（項目を切り詰めたときは件数が合わないため照合しない）。
- 項目数は 50 件に切り詰める。切り詰めた範囲に未充足の必須項目があるのに `allRequiredOk: true` なら不正。文字数は `id` 64 / `group` 40 / `label` 80 / `current` 200 / `hint` 600 に切り詰める。制御文字・見えない文字（`U+007F-009F`・ゼロ幅・向き制御）は空白 1 つにまとめる。
- `commands` は 1 項目あたり 3 件まで。**切り詰めると別のコマンドになるため**、400 文字を超えるもの・複数行のもの・制御文字や見えない文字を含むもの・文字列でないものは、切り詰めずにそのコマンドだけ捨てる。
- `reason` は既知の 3 値だけ残す。`target` は `external` 以外をすべて「セットアップで設定するもの」に寄せる。

### 表示の安全

- `doctor` の文字列は `textContent` だけで描く（`innerHTML` 系は使わない。テストで固定）。
- コマンドは**コピーするだけで実行しない**（既存の上限付きコピー経路 `VKClipboard.writeText` を使う）。実行するのは検証を通った `setupPane` だけ。
- `claude '<prompt>'` を作る経路は `utils/setupPaneLaunch.js` の 1 本だけ。検証済みの `prompt` 以外は例外にする。renderer からは作業フォルダもプロンプトも受け取らず、`terminal:create` に `setupPane: true` とだけ伝える（main が保持する検証済みの値を使う）。

## 確認の扱い

- 待ち時間の上限は 20 秒。同時に走らせる確認は 1 本だけ（実行中に呼ばれたら同じ結果を共有する）。時間切れで `signal` を abort する。**元の `getSetupStatus` が終わる（signal で止まる）までは「実行中」とみなし、新しい確認は始めずに時間切れとして返す**（古い確認と新しい確認が同時に走らないように。組み込み側は signal を受けて処理を止めること）。実装は `utils/setupStatusCheck.js`。
- 失敗・時間切れ・形の不正のいずれでも「セットアップ状況を確認できませんでした」＋理由＋「もう一度確認」「詳細をコピー」を出す。**「セットアップ済み」の扱いには倒さない**。
  - 時間切れ: 「確認に {秒} 秒以上かかったため、途中で止めました。」
  - 起動できなかった: 「確認用のプログラムを起動できませんでした。」
  - 形の不正: 「確認結果を読み取れませんでした。」（実装時に足した文言）
  - 「詳細をコピー」の中身は、理由・（あれば）エラーメッセージ（300 文字まで）・確認時刻だけ。
- 判定が出るまで、停止表示の文言は変えない（ちらつき防止）。確認に失敗しても、サイドバーの停止表示は直近に確認できた判定のまま保つ。
- 失敗したときは、直近に確認できた一覧を消さず、失敗の帯（理由・「もう一度確認」「詳細をコピー」・最終確認の時刻）を一覧の上に出して、一覧を薄く残す。
- 起動時の確認は、ウィンドウの用意と並行して main が先に始める。

## パネルの表示

### 組み立てる条件と置き場所

- **未完了のとき、または確認できなかったときだけ**組み立てる。セットアップ済みなら今と同じ画面（パネルも帯も作らない）。
- ペインの右に並べる。状態は 3 つ。
  - 主役（main）: セットアップ用ペインが無いとき。幅 440px。
  - 並べる（side）: セットアップ用ペインが開いているとき。幅 360px。幅が足りないときはパネルが縮み（下限 240px）、ペイン側（グリッド）も 320px を確保する。
  - 畳む（folded）: 「閉じる」を押したとき。上端の 1 行の帯「セットアップ未完了（残り n 件）。一覧を開いて進めてください［一覧を開く］」。
- ウィンドウ幅が 1000px 未満のときは、自動で「畳む」状態にする（ターミナルが潰れるため）。利用者が「一覧を開く」を押したときだけ開き、幅が 1000px 以上に戻ったら通常に戻る。1000px 未満で開いたパネルは、ターミナルを潰さず（グリッドの幅は変えず）グリッドの上に右寄せで重ねて出す（幅は 360px か、残りの領域の幅のどちらか小さい方）。サイドバーを開いた状態でウィンドウの最小幅 600px でも「閉じる」が画面内に見える。重ねたパネルはグリッドのリサイズ帯（z-index 6）より上（z-index 7）に出し、ペインが複数あってもボタンが押せる。上端の帯の文言は「。」の後ろで折り返す（文ごとに別 span）。
- 完了後は「セットアップが完了しました」を出し、「閉じる」で消す（帯にも残さない）。自動では消さない。消したあとは、直前に使っていたターミナルへフォーカスを戻す。
- モバイル画面は今回の対象外（認証付きの受け口を新設する必要があり最小構成を超えるうえ、導入作業はパソコンでしかできないため）。

### 一覧の並び

- 「自分で入れるもの」（`target: 'external'`）を先、「セットアップで設定するもの」を後。
- 各グループの中で必須と任意を見出しで分ける（「必須（残り n 件）」「任意（未設定 n 件）」。色だけで区別しない）。
- 充足済みは件数だけ（「そろっている項目 n 件」。開くと一覧）。
- Claude Code（`id: 'claude'`）の行が未充足なら、必須の先頭に置き「まずここから」を添える。
- 「セットアップで設定するもの」は `hint`（設定ファイルの書き換え方）を出さず「『セットアップを始める』で設定します。」とし、元の文は「詳しく」に畳む。

### ボタン

- 主「セットアップを始める」、副「もう一度確認」、横に「最終確認 HH:MM」。
- セットアップ用ペインには 2 種類ある。Claude Code が無いまま初回自動オープンされたペインは **Claude 無しのシェル（plain）** で、「Claude 付きのセットアップ用ペイン」としては扱わない。plain のペインが開いている間は「信頼しますか」の案内を出さず、「このペインで Claude Code を入れてください。入れたら「もう一度確認」を押してください。」を出す。Claude Code が `ok` になったら「セットアップを始める」を押せるようにし、Claude 付きのペインを開く（「セットアップ用のペインを表示」に変わるのは Claude 付きのペインが開いているときだけ）。
- Claude Code の行が `ok` でなければ「セットアップを始める」は押せない状態で残し（`aria-disabled`。キーボードで理由を読めるようフォーカスは残す）、すぐ下に「先に Claude Code を入れてください」を添える。
- セットアップ用ペインが開いていれば「セットアップ用のペインを表示」に変え、フォーカスを移すだけ（2 枚目は開かない。格納中なら戻す）。
- 確認中は「確認しています…」で押せなくし、`aria-busy` を付け、一覧は消さずに薄くする。
- 並べる状態の案内（Claude 付きのペインが開いているときだけ）: 「Claude Code が『このフォルダを信頼しますか』と聞いてきたら、Enter で進めてください。」
- 幅が狭いとき（パネルの本文幅 380px 以下）はボタンを 2 段に積み、幅をそろえる。
- 結果の変化・確認の開始（「確認しています…」）・「コピーしました」は `role="status"` で読み上げる（同じ文言を読み直させるときだけ、次の描画で入れ直す）。

### 文言（植草案）

- 見出し: 「VK Orchestrator のセットアップ」
- 説明: 「あと {n} 件で使えるようになります。上から順に進めてください。」
- コピー: 「コピー」→「コピーしました」
- サイドバー: 「セットアップ未完了のため停止中」「セットアップ状況を見る」

### 見た目

- 色は既存のダークテーマ（`--vktm--*` の変数、サイドバーのカードの配色）に揃える。
- コマンド枠の文字と背景は 4.5:1 以上（実測 17:1。e2e で確認）。
- コマンドは**折り返して全文を見せる**（`white-space: pre-wrap` と `word-break: break-all`。見切れて確かめられないまま貼ることを避けるため、司の判断で「横スクロール」から変更）。コマンド 1 件は `role="group"`＋`aria-label` で包む。

## サイドバーの停止表示

- `summary.allRequiredOk === false` で、タスクの宣言が無い・または古いとき: タスク欄を隠さず「セットアップ未完了のため停止中」と「セットアップ状況を見る」リンクを出す。リンクを押すとパネルを開き（畳んでいれば戻し）、見出しへフォーカスを移す。
- セットアップ済みなのに古いときは今と同じ「Orchestrator 停止中」。理由が分からないとき（判定が出ていない）も今の文言のまま。

## 初回の自動オープン

- このパソコンで**初めて「未完了」と判定されたとき 1 回だけ**、起動時に必ず作るペインそのものをセットアップ用ペインにする（2 枚目を足さない）。
- Claude Code が無いときは、Claude 無しのシェルで開き、`command not found` を見せない。
- 判断は起動時の確認結果を最大 5 秒待って行う。間に合わないとき・確認できなかったときは通常のペインで開き、自動では開かず記録も残さない（次回また判断する）。
- 記録は `~/.vk-terminals/setup-auto-open.json`（`{ "openedAt": ISO 時刻 }`）。vk-orchestrator の `setup.completedAt` には書かない。記録が読めない・書けないときは自動で開かない側へ倒す。実装は `utils/setupAutoOpen.js`。
- セットアップ用ペインには `initialCommand` を送らない（セットアップの最初のプロンプトと混ざるため）。セットアップ用ペインは「最初のターミナル」に数えないので、次の通常のペインに `initialCommand` が送られる。
- 起動時にセットアップ用ペインの作成に失敗したら、ログを残して通常のペインで開く（記録は書き終えている）。
- セットアップ用ペインの作業フォルダが消えていたら、ホームへ切り替えず作成失敗として返す。

## 完了後

- 一覧に「セットアップが完了しました」を出し、「閉じる」で閉じる（自動では消さない）。
- 司令塔（エンジン）を起動するのは組み込み側（vk-orchestrator#641）の担当で、vk-terminals は起動しない。
