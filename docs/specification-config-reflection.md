# 保存後の設定反映と通知

main が5秒ごとに本体設定と `config-reflection.json` を読み直す。renderer からの `app:config-reflection` invoke は現在のスナップショットを返すだけで、変化は `app:config-reflection-updated` で配信する。設定パネルからの保存成功時も main が直ちに読み直す。

対象は `newPaneStartupDir`、`newPaneAutoLaunchClaude`、`confirmClose`、`terminalLinkClickMode`、`menuItems`、`waitingExcludeCwdPatterns`。起動時と再読込時は同じ正規化を使い、不正な個別値は既定値へ寄せる。確認方法とリンク操作は既存の共通定数・正規化、入力待ち除外は既存の正規化を使う。renderer は毎回対象値をまとめて受け取り、差分は通知の判断だけに使う。開いているペインは変えない。メニューと main の入力待ち除外も renderer の監視に依存せず更新する。

本体設定の探索順は起動時と同じ。起動時も再読込時も通常ファイルかつ1,048,576バイト以下のJSONオブジェクトだけを採用する。JSON破損・読み取り失敗・形式不正・メニュー検証失敗なら直前の対象値を維持する。起動時のメニュー検証失敗は従来同様に空メニューとし、以後の再読込で復旧できる。起動時の設定読み込み失敗後も既定値を基準に差分を検出する。

起動時からある反映 `eventId` は通知しない。新しいIDまたは対象値の差分があり、失敗ファイルが無い場合に1.2秒待って再起動要否を再取得する。取得できれば「設定を反映しました」または「一部の設定を反映しました」を成功用トーストで通知する。取得失敗・不正応答は未確認として、直前の再起動案内を維持し通知を次の再取得まで保留する。同じ文言の通知は6秒以内ならまとめるが、常設案内の更新は省略しない。全部反映から一部反映など文言が変われば6秒以内でも通知する。訂正通知は実際の反映通知から15秒以内に限り、訂正自体では期限を延長しない。常設の部分反映案内は、この起動中に実際の反映があった場合だけ再起動要否に追従し、false なら消す。反映結果などの状態ファイルの上限は65,536バイトとする。

本体設定と反映結果の失敗ファイルを合わせ、サイドバーと設定パネル上部へ対象ファイル・修正と保存を促す文言を常設する。ファイル集合が変わった場合だけDOMを更新し、初回の失敗と復旧はそれぞれ一度トーストの status で知らせる。カード自体は live region にしない。失敗中の反映イベントは消費し、実際の設定差分は復旧まで保持する。復旧後、保持した差分または新しいイベントがあれば反映通知を出す。

保存メッセージは「保存しました。反映状況は設定の案内をご確認ください。」とする。保存後の読み直しで失敗があれば失敗結果へ更新し、自動で設定パネルを閉じない。対象6項目以外のみの保存にも中立な完結した文言を使う。

状態ファイルは別々に更新されるため、通知前の1.2秒待ちだけでは更新順のずれを完全には同期できない。再取得により常設案内と通知文言を修正する。現時点のOrchestratorは対象6項目も再起動対象とするため、変更時に部分反映案内が出る。

再起動要否が3回連続で未確認の場合は、固定文言と `restart-required.json` のファイル名だけを console.warn で一度記録し、確認できた時点で連続回数をリセットする。
