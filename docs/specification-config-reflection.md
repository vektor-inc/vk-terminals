# 保存後の設定反映と通知

VK Terminals は `~/.vk-terminals/config.json` の `newPaneStartupDir`、`newPaneAutoLaunchClaude`、`confirmClose`、`terminalLinkClickMode`、`menuItems`、`waitingExcludeCwdPatterns` を5秒ごとに再読込する。通常ファイルかつ65,536バイト以下のJSONだけを採用し、対象値を一括検証して差分のみ適用する。開いているペインは変えない。メニューは既存の更新処理、入力待ち除外はmainとrenderer双方の次回判定に反映する。

同じ周期で `config-reflection.json` の `eventId` と `failedFiles` を読む。起動直後のイベントIDは既知として通知しない。新しいIDまたは対象キーの実際の変更があり、失敗ファイルが無い場合に通知を予約する。1.2秒待って `restart-required.json` を読み直し、再起動が必要なら「一部の設定を反映しました」、そうでなければ「設定を反映しました」を5秒で消える読み上げ対応トーストへ出す。6秒以内の近接イベントは1件にまとめる。再起動が必要な場合、サイドバーと設定タブの常設案内に「残りの設定は再起動後に反映されます」を足し、再起動要否がfalseになれば消す。

両状態ファイルは別々に原子的に更新される。通知前の1.2秒待ちと再起動要否の再取得で通常の更新順のずれを減らすが、5秒の監視周期を超えるずれは完全には同期できない。常設案内は次の再取得で正しい状態へ収束する。現時点のOrchestratorはこの6項目も再起動対象とするため、変更時に部分反映の案内が出る。

本体設定の破損・読み取り失敗・対象値の型不正では直前の対象設定を維持する。Orchestratorの `failedFiles` も合わせ、失敗したファイルのパスと修正を促す文言をサイドバーへ常設する。内部エラーは表示しない。復旧後は失敗表示を消し、実際の差分または新しい反映イベントがある場合のみ通知する。
