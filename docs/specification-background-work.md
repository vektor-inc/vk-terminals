# 裏の作業とペインの「実行中」表示

## 利用者に見える動作

Claude Code の裏でコマンド（Codex の起動を含む）またはサブエージェントが作業している間は、出力が途切れても「実行中」を表示する。文字入力の直後にも表示を保つ。件数や専用の色は追加しない。

表示の優先順位は、入力待ち ＞ 完了 ＞ 見守り中 ＞ 実行中。`renderer/statusPresentation.js` が文言と色を決める。バッジのツールチップに「裏で作業が動いています」を添える。格納カードとモバイルカードにも反映する。

裏の作業中にペインを閉じる確認はバッジと同じラベルを使う。実行中・入力待ちは「このペインは「入力待ち」です（裏で作業が動いています）。閉じるとセッションは失われます。閉じますか？」の形式、完了・見守り中は「このペインは「完了」ですが、裏で作業が動いています。閉じるとセッションは失われます。閉じますか？」の形式とする。モバイルではペイン名も添える。デスクトップの確認頻度は利用者の閉じる確認設定に従う。

## 状態の責務

- `status`: 既存の出力・入力・待ちに基づく API の状態。意味と値を維持する。vk-orchestrator の入力再送判断もこの値を利用する。
- `displayStatus`: 表示用の状態。`renderer/statusState.js` の純粋関数で、裏の作業を実行中の根拠に加える。
- `backgroundWorkRunning`: 確認できた裏の作業があることを示す、追加のみの真偽値。
- `backgroundAgents`: 画面のエージェント数。待機メンバーを含みコマンドを含まないため、今回の根拠や件数バッジには使わない。
- `agentCommandState`: AI 本体の生存状態。生きているだけでは裏の作業とはしない。

裏の作業に入力直後200ミリ秒のガードを適用しない。1.5秒の出力停止タイマーでは裏の作業を含めて再計算し、終了通知では即座に再計算する。通知・ビープは既存の入力待ち判定に従う。サイドバーのタスク欄は tasks-widget.json を描画するため対象外。

## コマンドの検知

`utils/agentLifecycle.js` が現在の起動世代で取得した、PTY シェル直下の AI コマンドの PID と起動時刻を起点にする。共通の `ps` 表取得・親子関係判定を再利用し、Claude Code ペインだけを1秒ごとに調べる。

起点の子孫のうち、起点と異なるプロセスグループ、かつ制御端末を持たない（`tpgid <= 0`、macOS の実測値は 0）プロセスを候補にする。孫以降の多段シェルも対象。起点の開始時刻比較は agentLifecycle の isSameProcessStart を共有する。running の世代がなければ定期 ps を省く。同じ PID と起動時刻が連続する2回の確認に存在する場合だけ数える。短命なフックやステータス行の子による点滅を抑える。ゾンビ・消滅済みプロセスは数えない。

常駐 MCP サーバー・caffeinate は実測上 Claude Code と同じプロセスグループに属するため対象外。`ps` 失敗はコマンドの実行中の根拠にしないが、フックで記録済みのサブエージェントは維持する。親の同定失敗時は解除する。コマンドは生存を直接確認するため10分の上限を適用しない。消滅は次の定期確認で解除する。

## サブエージェントの検知

Claude Code の起動設定へ `SessionStart` / `SubagentStart` / `SubagentStop` コマンドフックを追加する。既存の `utils/claudeSettingsPreset.js` の配布経路で起動ごとの設定ファイルを作り、既存の Stop / PreToolUse フックを保持する。通常起動と API の再起動が対象。ガイド・セットアップなどフック設定を渡さない起動、配布に必要な信頼できる Node.js が見つからない環境ではコマンドだけを監視する。

`vk-orchestrator-work-pane` プリセットでは Stop に加えて `PreToolUse`（matcher: `Bash|Read|Grep`、timeout: 5秒）から VK Orchestrator の `check-sensitive-output-hook` を呼び出す。両イベントは同じ検証済み Node.js / entry の絶対パスを使う。`src/engine/sensitive-output-hook.js` が存在しない、または信頼できない場合はプリセットを生成せず `Claude settings preset hook is unavailable` とする。

フックは非 loopback 接続時に既存 HTTP API の認証ゲートを通る（loopback 既定では Bearer 照合を省略し、全接続で Origin と epoch を検証する） `POST /api/background-work` へ通知する。Bearer トークン・ペイン ID・起動ごとの乱数 epoch を接続ファイルへ保存する。ファイルは0600、親ディレクトリは0700。認証情報をコマンド行へ含めない。会話本文は転送しない。再起動は設定と epoch を別に準備し、停止と起動の成功時に接続ファイルと記録を切り替える。停止失敗時は新しい設定だけを捨てる。ペイン終了で接続ファイルと記録を解除し、古い epoch の通知を拒否する。同じプロセス内でセッションが切り替わった場合も、旧セッションの記録と遅延通知を除く。

開始を `agent_id` 単位で記録し、終了は次の早いほうで解除する。

1. 同じ `agent_id` の `SubagentStop`。
2. 同じ `agent_id` の `agent-<agent_id>.meta.json` にある `finished: true`。

フックの `agent_transcript_path`、または親の `transcript_path` から記録の場所を求める。`~/.claude/projects/<project>/<session_id>.jsonl` と `<session_id>/subagents/agent-<agent_id>.jsonl` の想定形のみ受け付け、ID・パスの組み合わせを検証する。実パスとの一致でシンボリックリンク経由の読み取りも拒否する。通常ファイルだけを読み、メタ情報は64 KiBを上限とする。フック標準入力は8 MiB、転送する識別情報は64 KiBを上限とする。

動きの確認には同じ agent_id の jsonl の更新時刻を使う。開始時刻または最後に確認できた更新から10分で必ず解除する。ファイルが読めなくても開始から10分で解除する。名前付きエージェントが完了後に待機する場合も、finished または上限で解除する。終了済み ID の遅れた開始通知では復活させない。AI 本体の終了・ペインの終了・再起動の世代交代で全件解除する。

## 実機で確認した範囲

Claude Code 2.1.319、macOS、haiku、使い捨てディレクトリで確認した。

- 通常の Agent と、`name` / `run_in_background: true` を指定するよう依頼した Agent の開始・完了で、同じ `agent_id` の SubagentStart / SubagentStop を観測した。名前付きの試験では完了通知を待ってから親の応答が終了した。
- 開始入力には session_id / transcript_path / cwd / prompt_id / agent_id / agent_type / hook_event_name がある。
- 終了入力には agent_transcript_path / last_assistant_message / background_tasks などもある。通知では必要な識別情報だけを送る。
- Bash のバックグラウンド実行から多段シェルと sleep を起動した前回の試験で、子孫は Claude Code の配下に残った。Claude → zsh → sh → sh → sleep の親子関係と、Claude と別の PGID、tty なしを確認した。実際の Codex は呼び出していない。
- 今回の試験は `claude -p` の短い実行。長時間常駐する実運用ペインのブラウザ操作と UI の実画面照合は別途行う。TeammateIdle は今回の終了判定には使用しない。

## 制約と採らなかった案

ファイルの配置は確認した Claude Code の形式に依存する。将来の形式変更、ファイルの読み取り失敗、極端に長い無出力の思考では10分で解除される。API トークンを再発行した場合、既存フックの接続ファイルは起動時のトークンのため、ペインを再起動して配布し直す。

画面の `← N agents`、プロセスだけでのサブエージェント検知、transcript-evidence API の流用、AI 本体の生存状態の流用は採用しない。「裏で実行中」へのラベル分離は出力の途切れによる切り替わりを避けるため採用しない。待機メンバーだけを根拠に閉じる確認を出す方式も採用しない。

前面のコマンド実行中も裏の作業と同じ扱いになる（ラベルは正しいが理由の文言はやや広い）。run_in_background の終わらないコマンド（開発サーバー等）は動いている間「実行中」が続く。

設定ディレクトリには所有者 PID と起動時刻を記録し、次回起動時に所有者の消滅を確認したものだけ回収する。生存中・PID 再利用・所有者不明のディレクトリは残す。終了時に定期監視タイマーも解除する。

## セッション再開（`/resume`）

同じ AI プロセスで別セッションへ切り替えると、以前のサブエージェント記録を消し、旧セッションから遅れて届く開始・終了通知を拒否する。`SessionStart`（セッション開始通知）は source が未指定または resume の場合に退役済みのセッションでも受け付けるため、A → B → A の順に `/resume` で戻れる。再開後のサブエージェントは新たな開始通知から記録する。裏のコマンドはプロセスの生存を根拠にするため、セッションの切り替えでは解除しない。

SessionStart の入力には開始理由を表す source がある。Claude Code 2.1.319 の実行ファイルでは startup / resume / clear / compact / fork を確認している。退役済みセッションの startup などは拒否する。

制約として、遅延した resume の通知だけは正当な再開と区別できない。互換性のため source 未指定の通知も受け付ける。`/resume` が session_id を保持するかは実機では未確認であり、A → B → A の復帰は単体テストで確認している。

## 組み込みアプリのフック起動元（#573）

`embedded.start()` による組み込み起動かつ `app.isPackaged === true` の場合だけ、main プロセスが `process.execPath` をフック起動元として選ぶ。プリセットの Stop / PreToolUse とバックグラウンド作業の各フックに共通で適用する。HTTP API のリクエスト値からは指定できない。

起動元は祖先ディレクトリ・リンクを含む既存の所有者・書き込み権限検査を通した、実行権限のある通常ファイルに限る。入力パスと解決後パスの両方で、絶対パスかつ制御文字を含まないことを要求する。空白や引用符はシェル引数として引用する。

コマンドは `/usr/bin/env ELECTRON_RUN_AS_NODE=1 '<execPath>' '<entry>' ...` とする。シェル固有の環境変数代入構文を避け、変数はフックの子プロセスだけに適用する。PTY の環境変数には追加しない。検証失敗時はプリセットを unavailable とし、バックグラウンド作業フックも使用しない。

通常起動・開発起動・CLI では信頼できる node の探索と従来のパス文字制限を維持する。アプリ版ではフックのスクリプトと VK Orchestrator の入口が ASAR の外の実ファイルとして配置されることを前提とする。
