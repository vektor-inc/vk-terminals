# アプリ内ブラウザ仕様（issue #590）

## クリック操作

ペイン内 URL、issue タイトル、PR ボタンをクリックするとリンクのそばに「アプリ内で開く」「外部ブラウザで開く ↗」のメニューを出す。開き先を選ぶまではページを開かない。未フォーカスのペインでも最初のクリックで表示する。ペイン内 URL は既存の `terminalLinkClickMode` が `click` なら通常クリック、`modifier` なら ⌘ / Ctrl+クリックでメニューを出す。タイトルと PR は設定に関係なく通常クリックで表示する。修飾キーによる直接起動と新しい設定項目は設けない。

Claude Code と Codex のペイン内 URL は、文字列から検出したリンクと端末の OSC 8 リンクのどちらも同じクリック判定と開き先メニューを使う。

ドラッグ、右クリック、中クリック、ダブルクリックの 2 回目では表示しない。Esc、Tab、外側クリック、ペインのホイールで閉じ、上下矢印で移動し Enter / Space で決定する。メニューは `role=menu` / `menuitem`。ペイン内 URL はクリック位置の右下、タイトルと PR は要素の左下に置き、画面端とサイドバー左端を超えない。初期フォーカスは「アプリ内で開く」。閉じたら元のペインまたは要素にフォーカスを戻す。

## 右サイドバー

再読み込みは、確定した HTTP(S) の URL または再試行できる失敗 URL がある場合に有効にする。初回の URL 送信だけでは有効にせず、文書が未確定の読み込み中は無効にする。表示済みページからの読み込み中は、確定 URL があるため再読み込みできる。

右側に 1 枚を使い回し、新しいリンクはページを差し替える。上部の操作は戻る、進む、再読み込み、URL 入力欄、外部ブラウザで開く、閉じる。URL 入力欄へ URL または検索語を入力し、Enter でページを開く。URL のコピー操作は設けない。入力欄は未送信の入力を編集中は保持し、送信後は読み込み先、失敗時は失敗した URL を表示する。外部ブラウザボタンは入力欄の表示とは別に、確定した現在の URL（または一致するダウンロード要求で明示した対象）だけを開く。読み込み中は進行バー、失敗時は失敗先のホスト名と再読み込み・外部ブラウザで開く操作を表示し、後続の読み込み状態通知でも保持する。次の遷移で消す。失敗表示の外部ブラウザ操作は読み込みに失敗した URL を開く。外部ブラウザで開く前に URL を検証する。github.com の 404 ではプライベートリポジトリへのログイン案内と「GitHub にログイン」「閉じる」を表示し、次の遷移まで保持する。

幅は左端のドラッグまたは矢印キーで変更する。通常の下限は 360px、既定は左サイドバーと横並び要素の最小幅を除いた使用可能幅の 45%（480〜720px）。中央のターミナルには `MIN_TERMINAL_WIDTH = 320px` を確保する。左右のサイドバーの併存は、root の CSS 幅から左サイドバーの設定幅を引いた残幅が `320px + 360px` 未満なら不可とする（左が 300px なら root 幅 980px 未満）。右のブラウザを開く、または表示中に幅が狭くなると左を閉じる。左を手動で開いた場合は右を閉じ、その操作を優先する。判定には開閉途中の左の実幅ではなく設定幅を使う。右を閉じても左は自動で開かず、幅を広げても閉じた側は自動で開かない。

左右の排他処理後、表示中の左サイドバーの実幅を除いた幅に「ブラウザ下限 360px ＋ 横並びのペイン予約幅 `max(.grid の横並び時の最小幅, 320px, 列数 × 272px)` ＋ セットアップ状況パネル最小幅 240px」が収まらない場合に、セットアップ状況パネルを帯に畳む。この判定はブラウザの保存幅に依存せず、左右の排他判定とは別に行う。たとえば左 300px・root 980px では左右は併存できるが、セットアップ状況パネルは帯になる。ブラウザを閉じると root 幅 1000px 未満で畳む判定に戻る。帯の「開く」は既存の影つき重ね表示を使う。帯・重ね表示は横並び要素として幅を引かず、横並びのパネルだけ最小幅 240px を引く。

ブラウザ幅の計算に使うグリッド最小幅は常に 320px 以上とする。帯に畳んだ後も `max(MIN_TERMINAL_WIDTH, 12px) = 320px` であり、パネルなし・重ね表示でも 320px を残す。上限は `min(max(0, 使用可能幅 − グリッド最小幅), max(360px, 使用可能幅 − max(グリッド最小幅, 320px, 列数 × 272px)), root の CSS 幅 − 96px)`。中央 320px の確保によって上限が 360px 未満になる場合は、ブラウザを 360px 未満に縮める（root 600px・左を閉じた状態ではブラウザ 280px、中央 320px）。配置切替後はブラウザ表示幅を再計算する。希望幅は `localStorage` の `vk-terminals.internalBrowserWidth` に保存し、狭幅による表示幅の制限や左右の開閉では上書きしない。幅を広げると保存した希望幅を現在の上限内で再び使う。

root の CSS 幅が `320px + 240px = 560px` 未満では、中央 320px と操作列を使える幅 240px を横並びにできないため、ブラウザを root 全体に重ねて表示する（全面表示）。全面表示中は背後のペインとサイドバーを `inert` にして操作対象から外し、操作列へフォーカスを移す。幅が戻って全面表示を解除すると、全面表示へ入る前にフォーカスがあった要素へ戻す。ウィンドウの最小幅は 600px のため、表示を拡大しているときに該当する。

トーストは画面左端 + 16px からアプリ内ブラウザ左端 − 16px の範囲に置き、左サイドバーの上にも重ねる。最大幅は `min(320px, calc(100vw - アプリ内ブラウザの幅 - 32px))` とし、置ける幅が 200px 未満なら案内文を折り返す。全面表示ではブラウザの左に置ける範囲がないため、トーストを通常の右下（最大幅 `min(320px, calc(100vw - 32px))`）に出し、表示中だけページ領域の下端をトースト上端の 8px 上まで詰める。トーストの高さが変わればその都度詰め直し、消えたらページ領域を元に戻す。トーストは全面表示中も `body` 直下に置いたままにし、モーダル表示中も操作と読み上げの対象に残す。開閉・幅変更時にペインを再フィットし、ドラッグ中はページを一時的に隠す。アプリ起動時は閉じ、ページは復元しない。閉じても同じ起動中はページを保持し、タイトルバーの切替ボタンから再表示できる。未表示のときは案内文を表示する。

モーダル表示中は WebContentsView のページだけを隠し、全て閉じると再表示する。選択メニューでは隠さない。ペイン内リンクからアプリ内で開いた後のフォーカスは元のペインへ戻す。タイトルバーから空のアプリ内ブラウザを開いた場合は URL 入力欄へフォーカスし、ページを保持したまま再表示する場合は操作元のフォーカスを維持する。トーストとリンクのツールチップはページの左側に収める（全面表示中のトーストは上記のとおり右下）。

## 保存領域と安全性

WebContentsView は `persist:vk-terminals-internal-browser` を使用し、ターミナル側と Cookie を分ける。単体版と同梱版の保存場所も分かれる。`sandbox: true`、`nodeIntegration: false`、`contextIsolation: true`、`webSecurity: true`、`allowRunningInsecureContent: false`。preload は渡さない。通常の開く URL は HTTP(S) のみ。組み込みの案内ページだけ `vk-terminals-help://guide/` をページ遷移・リダイレクト・新規ウィンドウ要求の例外として受け付ける。クエリ・別パス・別ファイル・`file:` は拒否し、ハッシュだけを許可する。専用プロトコルは特権スキーム登録を使わず、登録済み `help.documentPath` の HTML のみを返す。実体パスと一致しないリンクは拒否し、`O_NOFOLLOW` で開いた同じ fd から読む。応答には `Content-Security-Policy: frame-ancestors 'none'` と `X-Content-Type-Options: nosniff` を付ける。不正なアドレスや読み込み失敗はネットワークエラーとして扱う。案内ページ内の HTTPS リンクは同じサイドバーへ移動し、戻る操作で案内へ戻る。戻る・進むは Electron の履歴に従う。案内からリンク先へ進んだ後は、戻るで案内に戻り、さらに戻ると案内より前のページへ戻る。進むでリンク先へ再度進める。案内ページで外部ブラウザを選ぶと main 側が登録済み HTML の file URL と現在のハッシュを組み立てる。外部ブラウザで開けなければ再試行を促す通知を表示する。新規ウィンドウは作らず同じサイドバーに開く。専用セッションの権限要求は全て拒否する。証明書エラーの回避は設けない。IPC の送信元と座標を検証する。終了と再起動で WebContentsView を破棄する。

ログイン状態は再起動後も保持するが、外部ブラウザのログインは引き継がない。ログアウトは GitHub 上で行う。パスワードと認証アプリのコード、GitHub Mobile 承認、パスキー、企業 SSO の実機確認結果は未確認（PR で記録）。

モバイル表示、開閉ショートカットは対象外。

## レビュー後の決定

ページが離脱を阻止したときは、メインウィンドウを親に、メッセージ「このページを離れますか？」の確認を出す（Windows・Linux のタイトルも同じ）。詳細文は「入力中の内容は保存されない可能性があります。」、操作は「移動する」「このページにとどまる」とし、既定・キャンセルは「とどまる」。移動を選んだときだけ離脱を許す。

メニュー表示中に矢印・Home・End・Enter・Space・Esc・Tab 以外のキーを押したときは、メニューを閉じて元のペインの端末へフォーカスを戻す。キーは端末へ送らない。Shift・Alt・Meta・Control 単独と日本語入力の変換中は閉じずに無視する。初期フォーカスは「アプリ内で開く」。

アプリ内ブラウザのダウンロード要求は取り消す。Enter で開こうとした URL と一致するときだけ、その URL を操作列の外部ブラウザボタンの対象に設定してから「ダウンロードはできません。操作列の「外部ブラウザで開く」から行ってください。」とトーストを出す。一致しないときは操作列の対象を変えず、「ダウンロードはできません。外部ブラウザでダウンロードしてください。」と案内する。ダウンロード阻止の読み上げは通常トーストに集約する。持続トーストが表示中で新しいトーストを出せない場合だけ、持続表示を保ったままアプリ内ブラウザの live status で同じ結果と回復操作を読み上げる。
